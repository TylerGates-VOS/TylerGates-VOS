## 👋 About me

I'm the Director of Engineering Support at **VOS Systems**, where we build RFID reader kits and connected safety devices. I sit between the field, engineering and our partners: I install and tune hardware on site, dig into the data when something looks off, and turn repeat problems into tools so nobody has to solve them twice.

- 🔭 **Currently:** improving kit read reliability through antenna positioning and signal analysis
- 🛠️ **Building:** internal desktop tools that replace scripts and spreadsheets
- 📚 **Learning:** network and security fundamentals (CompTIA Network+ → Security+)
- 🎓 **Education:** B.S. Computer Software Engineering, Johnson & Wales University
- ⚜️ **Eagle Scout**

## 🚀 Featured work

### VOS Pull &nbsp;<sub><sup>internal</sup></sub>
A native desktop app for pulling and validating RFID movement data from the VOS API.

- Native window on **Windows and Linux** (PySide6), no browser or local server
- Multiple pull modes, including one that mirrors a partner's scheduled job exactly
- Live progress with rows, pages, ETA and a seconds per page chart that flags API slowdowns
- Kit and tag filters, per day file splitting, cancel anytime, run history
- Session token stored in Windows Credential Manager or the Linux keyring, never the password
- Automated builds with GitHub Actions; secret scanning with gitleaks on every commit

`Python` `PySide6` `GraphQL` `PyInstaller` `GitHub Actions`

## 🧭 How I work

> **Measure first.** Pull the data, find the pattern, then touch the hardware.
>
> **Fix it once.** If I solve the same problem twice, it becomes a tool or a runbook.
>
> **Secure by default.** No passwords in files, least privilege everywhere, secrets never in git.
>
> **Write it down.** Clear notes for the next person, including future me.
